# Track II v1.0.13 — Native notifications and launch polish

This patch keeps the full release version for update safety while presenting a
compact two-part version label in the app. It preserves existing workout,
account, sync, and offline data.

## Native notifications

- Rest completion alerts are now scheduled with the iOS/Android operating
  system at the rest deadline, so they can arrive while Track II is in the
  background or its web view is suspended.
- Starting a new rest timer replaces the previous pending alert, stopping the
  timer cancels it, and restored timers schedule their remaining deadline
  again without duplicate notifications.
- Rest alerts and immediate client notifications use the Track II notification
  icon and foreground presentation settings. Alerts remain device-local and
  are never broadcast to other users.

## Native branding and launch experience

- Rebuilt the iOS icon manifest with valid iPhone, iPad, and App Store
  marketing slots so installed apps use the Track II logo instead of Apple’s
  placeholder icon.
- Added a generated transparent Android status-bar icon from the same source
  asset.
- Added a first-launch native intro with the centered Track II logo, a quiet
  heartbeat while app/auth loading continues, and a short scale-and-fade exit
  once the app is ready. The intro is shown once per installation and respects
  reduced-motion preferences.
- The web/native initial loader now uses the same logo-only heartbeat instead
  of a generic loading card.

## Timer and version clarity

- Custom rest input now uses `minutes.seconds` notation for short values:
  `0.3` means 30 seconds, `1.30` means 1 minute 30 seconds, and the field
  explains the format directly beside the input.
- Rest summaries and presets use explicit minutes/seconds copy to remove
  decimal-minute ambiguity.
- The in-app version badge uses a compact two-part display while full semver
  remains available to release comparisons and update checks.

## Notification center and account presence

- Added a per-account notification center for rest completion, sync problems,
  recovered workout drafts, and announcements, with persistent unread state,
  mark-read, mark-all-read, and dismiss actions.
- Admin status and account presence now refresh through the protected member
  heartbeat on every platform. The server still verifies admin access inside
  each protected operation; the client only reflects the latest verified
  result and connection state.
- Stabilized exercise and split overflow menus so they wait for a measured
  anchor before painting and remain inside the viewport instead of flashing at
  the top-left corner.

## Offline-first reliability

- Added a versioned service-worker app shell with update activation, stale
  cache cleanup, network-first navigation, and a dark offline fallback page so
  the app can open without a connection after its first successful load.
- Strengthened the encrypted local queue with cross-tab locking, exponential
  backoff with jitter, bounded retries, a visible stuck-item state, storage
  quota handling, and sync queue telemetry. Existing local snapshots remain
  intact when storage or network operations fail.
- Added stable notification delivery IDs and scheduled/displayed/opened/
  dismissed/failed telemetry so duplicate announcements and delayed client
  alerts can be diagnosed across web, iOS, and Android.
- Added a three-way sync review for the last shared base, this device’s edits,
  the cloud copy, and the merged result. Users can keep the merged copy, use
  the cloud copy, or retry without an automatic overwrite.

## Workout performance and coaching

- Virtualized long workout lists, memoized task cards and set rows, stabilized
  editor callbacks, cached the exercise catalog locally, debounced catalog
  search, and paused hidden-tab sync refreshes.
- Added a one-thumb complete-set action that marks the set locally and starts
  the existing rest timer without changing the saved workout payload.
- Smart Coach now requires multiple comparable sessions, considers target RIR,
  volume, fatigue and failures, reports confidence, explains its evidence, and
  offers accept/repeat/dismiss actions without automatically changing weight.
- Added additive progression-history database support and retained the
  existing workout data and sync migrations.

## UI and release quality

- Split workout-specific styles and extracted oversized editor, set-row,
  menu, progression-history, and page-header modules to keep future changes
  maintainable.
- Added iPad/mobile regression coverage for split switching, inbox and
  clear-all flows, Rank front/back switching, calendar reverse animation,
  bottom-navigation clearance, long workout scrolling, and visible set labels.
- Added a protected native-production workflow for release-signed Android
  APK/AAB and iOS IPA artifacts, with optional TestFlight upload. Signing keys
  stay in the protected CI environment and are never committed.
- Added live Pages verification hooks for HTML caching, immutable hashed
  assets, and Brotli delivery. SVG validation and regeneration instructions
  remain checked into the repository alongside the MIT notice.

## Verification

- Added regression coverage for background scheduling, native icon assets,
  native launch behavior, compact version formatting, and custom rest parsing.
- Full source build and test suite passes with 102 tests.
- Retained the distributed database-backed limiter and the existing protected
  server paths while making these client/native changes.
